# 随身摄像头寻药演示

说“帮我拿感冒药”“帮我拿发烧药”“走到头痛药前面”会进入专用视觉控制流程。
说“你面前有三瓶药，哪一瓶是感冒药？”会拍照确认目标颜色和左右位置，再直接播报识别结果；这类询问不触发行走。
单问“感冒药是什么颜色？”直接回答配置的演示对应关系，不声称看到了当前画面。
“停下”“停止寻药”及原有语音打断会取消当前寻药，发送 `self.otto.stop`。
功能范围是移动到目标前面并停下，未实现抓取。

用户在 2026-10-20 确认了演示对应关系：蓝色瓶子＝感冒药、绿色瓶子＝发烧药、橙色瓶子＝头痛药。
用户随后说明当前用三个不同颜色的易拉罐替代药瓶，本机已改用“蓝色易拉罐、绿色易拉罐、橙色易拉罐”作为目标描述。
这是人为约定的演示标识。发烧药/退烧药、头痛药/头疼药分别共用同一个目标。
真实药品身份不能从瓶子颜色推断。

## 控制流程

1. 用已配置的药名查找演示标识；未配置就提示补充对应关系。
2. 刷新 MCP 工具列表，确认摄像头和当前会话的 Otto 行走、停止、状态工具均已接通。
3. 停止既有动作，等待 idle，然后拍一张新的照片。
4. 视觉返回 `[match,x,h,clear]`：目标匹配标记、横向中心占画面宽度比例、目标高度占画面高度比例、可见地面通路是否清楚。
   同时兼容含 `match`、`x`、`h`、`clear` 的 JSON 对象，并执行相同的有效值检查。
5. 左右偏离时转一步，居中时前进一步；每次等动作完成再拍照。未见目标最多左转四次，曾找到后丢失就停止。
6. 连续两张照片中目标居中且达到停止大小时停止。单次最多前进六步、观察十二次、总计四分钟。
7. 看不清、位置格式不完整、地面通路不明、工具异常或打断均结束循环并发送停止指令。停止未确认时不播报成功。

执行使用真实 `look_at_camera`、`self_otto_action`、`self_otto_get_status` 和 `self_otto_stop`。
工具调用和定位数据保留在日志/当前对话中；不会把移动决策再交给聊天模型。

## 本地配置

运行 `main/xiaozhi-server/robot-navigation/configure_demo.py --container 易拉罐` 写入已确认的颜色映射，并备份原 `data/.config.yaml`。
`--container` 支持 `容器`、`瓶子`、`易拉罐`，默认使用通用的 `容器` 描述。
智控台模式同样保留这项本地配置。可调整示例：

```yaml
medicine_navigation:
  enabled: true
  identity_mode: marker
  targets:
    感冒药: 蓝色易拉罐
    发烧药: 绿色易拉罐
    退烧药: 绿色易拉罐
    头痛药: 橙色易拉罐
    头疼药: 橙色易拉罐
  max_observations: 12
  stop_height_ratio: 0.45
```

`identity_mode: label` 可改为读取药盒上的药名；默认配置为空映射，不自带任何药品颜色约定。

摄像头桥接的普通拍照提示词会截断长问题并要求中文短句，无法保留定位格式。
运行 `robot-navigation/patch_camera_bridge.py <camera_mcp.py绝对路径>` 给现有桥接增加 `NAV1 ` 提示词通道，
校验 URL 编码后不超过固件的 255 字符上限，原文件自动备份，然后重新加载摄像头 MCP 子进程。
该适配不需要重新烧录摄像头或机器人。

## 实机标定与边界

`stop_height_ratio` 是瓶子在画面中占据的高度比例，默认 0.45；它不是厘米距离。
需要根据实际瓶子高度、摄像头俯角、安装高度以及一步距离标定。先在平坦、通畅的地面放一个瓶子，
让瓶子与机器人处于同一地面，检查左右转向与画面一致，再逐项测试三个颜色。
摄像头要能同时看清目标和近处地面；只拍到桌上瓶子、没有看到机器人前方通路时会停止。
不同颜色瓶子要能清楚区分，同色多个瓶子会造成歧义。

这是低速、有限步数的视觉接近原型，没有深度测距、建图或专用避障传感器。
视觉模型不能保证可靠判断距离、障碍、台阶和地面边缘，当前实现不能作为可靠导航或自动取药完成的证明。

## 验证

服务端运行：`python -m unittest discover -s tests/core -p test_medicine_navigation.py -v`。
测试替换真实硬件，覆盖左右转向、前进、两帧停止、目标丢失、通路不明、异常、打断、工具缺失、次数上限和显式颜色映射。
`robot-navigation/verify_live_camera.py <mcp_server目录>` 只触发一次真实定位拍照，保存协议验证结果，不发出运动命令。
实机是否能稳定走到三个瓶子前面仍需在上述布置下验证。
