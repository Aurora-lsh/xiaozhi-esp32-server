# 本机语音对话提速记录

2026-10-19，保留现有 Qwen3.5-9B（Q4_K_M、16K 上下文）和 GPT-SoVITS 海绵宝宝音色，完成第一轮优化。

## 已部署的调整

- 先检索本地记忆；存在有意义的关键词匹配时，直接让 Qwen 结合结果回答，省去一次检索词扩展。缺少匹配时仍调用模型扩展同义词，继续支持“毛孩子”等不同表述。
- 自动记忆提取默认等待回复后空闲 10 秒。同一设备开始新一轮聊天时，取消尚未开始的任务；重新连接同样生效，不影响其他设备。
- 后台积压每次处理一个批次，再安排下一批，避免连续占用模型。原始聊天仍即时保存，模型异常时保留待处理原文。

参数及恢复原行为的方法见 [本地长期记忆配置](local-long-term-memory.md)。启动方式继续使用项目根目录的 `Start-Xiaozhi.ps1`。

73 项回归检查通过，覆盖记忆持久化、设备隔离、修改删除、同义词检索、空闲任务取消、跨会话取消、后台批次让出以及上下文限制。三次最终真实问答均正确匹配已保存的饮品记忆并返回语音。

## 流式合成与打断（2026-10-19）

- GPT-SoVITS v2 的 `streaming_mode` 支持 0–3。当前海绵宝宝模型设置为 2，`min_chunk_length=16`，语速、参考录音和权重沿用原配置。
- 逐块解析 WAV、连续重采样到设备的采样率，并以 60 ms Opus 帧送入原播放队列，不再等待整句 WAV 下载完成。首句优先在较早的停顿处切分，超过 32 字也会开始合成。
- 打断会取消当前合成 HTTP 请求和对应聊天模型流，同时废弃旧轮次编号。流式音频中断后不会重新播放已播出的句子；首帧之前失败可回退普通合成。
- 明确的纯讲故事请求省去工具描述和工具选择；含摄像头或设备指令的混合请求仍保留工具路径。
- 固件声明 `hello.features.response_status=true` 时，收到可选的 `thinking`、`speaking` 显示提示。旧固件沿用现有协议行为。

一次相同 80 字故事请求的实际 WebSocket 对比：首帧声音 9.282 秒 → 7.277 秒，整轮 31.965 秒 → 28.628 秒；两次回答分别为 73 字和 100 字。这是单次观察，包含模型输出差异，不代表稳定延迟保证。计时不含录音、识别和机器人扬声器延迟。

固定文字的 TTS 单独测量中，预热后的普通合成首块 PCM 为 1.510 秒，模式 2 为 1.179 秒。两种模式的合成策略不同，需要实机试听音色和韵律。

实际 24 kHz WebSocket 打断检查：发送打断到收到停止消息 0.003 秒，随后 0.5 秒没有旧音频帧。这个数值不包含设备本地已缓冲声音的停止时间。

105 项相关回归检查通过，涵盖记忆、故事、上下文、WAV 分块、流式故障回退、取消请求和状态协商。原文在线备份 `data/character-backup-20261019-233659.sqlite3` 已保存；更新后核验无待提取原文。实测统计与音频位于本机忽略目录 `.runtime/voice-streaming-20261020/`。

恢复普通合成：把当前 TTS 模型配置的 `streaming_mode` 改成 0，清理对应模型配置缓存并重启 Python 后端。其余旧值备份为同目录下的 `tts-before-*.json`。

## 句中断续处理（2026-10-21）

当前海绵宝宝语音配置已改为 `streaming_mode=0`，每段文字先完成合成再送入原音频播放队列；音色、模型权重和 `speed_factor=1.3` 保持原设置。原来的模式 2 在本次测量中生成约 7.56 秒音频用了 48.898 秒，音频块到达间隔最大为 17.666 秒，无法维持连续播放。

同时补齐 GPT-SoVITS 专用虚拟环境缺失的 `rich==15.0.0` 及其依赖，已验证 AR 加速模块可导入，并在实际服务中看到 `torch_static_cuda_graph` 后端被使用。相同测试文字的整段合成由补齐依赖前的 30.861 秒降至预热后的 14.339 秒；两次生成音频分别为 6.72 和 7.04 秒，包含当前机器负载与生成差异，不代表固定延迟。

整段合成避免句内等待下一块音频，但开始播放前仍需等待该段生成完成，句间仍可能等待下一段。已重启小智 Python 后端，实际扬声器连续性需由设备试听确认。修改前的模型配置保存在本机 `.runtime/voice-stutter-20261021/tts-before-025919.json`，恢复模式 2 可通过智控台模型配置修改，再重新连接设备。
