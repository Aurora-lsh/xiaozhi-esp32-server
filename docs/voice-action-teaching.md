# 语音教动作，然后按名称执行

先一次口述完整步骤，机器人保存并复述；之后用名称执行。

## 可以直接说的话

- 教学：“海绵宝宝，教你一个动作叫拿感冒药：先左转一步，再前进两步，最后停下。”
- 核对：“复述动作拿感冒药。”
- 执行：“执行拿感冒药。”或“执行动作拿感冒药。”
- 中止：“停下。”或“停止执行。”
- 查看：“你学会了哪些动作？”
- 更正：“把动作拿感冒药改为先右转一步，再前进三步，最后停下。”
- 删除：“删除动作拿感冒药。”

保存阶段不执行动作。只有整套步骤都能理解时才保存；如果有一步无法理解，原有同名动作保持原样。
再次教同名动作会更新步骤，机器人复述更新后的内容。执行时不会让聊天模型重新编排动作。

## 支持的步骤

前进、后退、左转、右转，使用“步”；挥手、举手、放下手、坐下、站起来或复位，使用“次”；
等待使用“秒”，以及停下。支持“一、两、三”等中文整数，也支持阿拉伯数字。
未说次数的动作按一次保存，并在复述中明确说出。
手部动作需要机器人本身有对应舵机，设备报告不支持时停止后续步骤。

例如：“先前进两步，然后左转一步，再等待两秒，最后挥手一次。”

每条最多十二项，每项一到十步或次，运动合计最多三十步或次；
每次等待一到十秒，等待合计最多三十秒，总执行时间最多两分钟。
当前未标定厘米和角度，“前进五米”“左转九十度”等表达会提示改用步数，不会自行换算。

## 执行和停止

每次发送一个单步动作，等待设备返回 idle，再发送下一步。
设备的动作接口只确认入队，因此不能把调用返回当成动作已结束。
执行失败、设备不确认动作或运动长时间未结束时，停止发送后续步骤并发送停止。
停止未收到确认时会明确提示检查设备，不播报成功。
原有语音打断、停止控制和断开连接清理同样适用于已学动作。
已学动作与视觉寻药共用同一会话的运动锁，开始新的执行会先中止旧任务。

这项功能按固定步骤重复，需要从相同起点和朝向开始。
药罐位置、起点或朝向变化后，需要重新教步骤；“执行拿感冒药”不会自动用摄像头寻找目标。
原有“帮我拿感冒药”仍使用视觉寻药流程。

## 本地保存

动作保存到当前 `local_memory.database_path` 指定的 SQLite 文件，默认
`main/xiaozhi-server/data/long_term_memory.sqlite3`，使用独立的 `learned_actions` 表。
每个设备独立保存名称、完整步骤、原始教学文字、消息来源和修订号，重启服务或重新连接后仍可读取。
动作教学由专用处理器接管，优先于普通记忆命令和角色聊天。
动作消息仍在本地聊天档案中保留，但排除出异步个人事实提取。
列表和复述通过上述语音命令读取，不依赖聊天模型推测。

## 验证

`python -m unittest tests.core.test_action_teaching tests.core.test_medicine_navigation tests.core.test_memory_connection -v`

测试使用模拟硬件和临时数据库，覆盖语音入口、完整步骤校验、保存后不运动、跨重连读取、设备隔离、
按名称执行、逐步等待、打断、目标名称不存在、工具错误和停止失败。
本次没有代替用户教入真实路线，也没有执行真实舵机动作；实机仍需用短步骤验证步长和转向。
